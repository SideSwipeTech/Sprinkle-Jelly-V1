# Solving

## Purpose

Solving provides the common coding-problem experience used by Challenges, Track problems, Daily Challenges and Debug Detective. It combines familiar controls without owning a global problem collection or a global completion record.

Each area supplies its own statement, runtime choices, starter, examples/cases, comparison policy, hints, learner status and submission action. The area owns its result, first-solve identity and rules for rewards/evidence. A similar problem elsewhere remains independent. A shared form, workbench or evaluator does not link their outcomes.

## The workbench

Keep the statement, editor, Run/submission controls, output/errors/visible-case results, optional custom input, hint ladder, Reset, applicable language choice, restored-draft message and resizable panes together. Render only regions the activity actually supports. The output pane has one active tab rather than duplicate terminal/result panels.

A single-language Track does not offer another runtime. A Debug clock and acknowledged checkpoint are supplied by Debug; the workbench does not run its own competing timer or allowance. Code Lab composes the applicable editor/output controls without a problem, Submit or cases. Assessment uses suitable controls inside its recorded-test lifecycle, not this Practice completion policy.

## One normal journey

**Open owned problem → read rules → choose an offered language → edit → Run → Submit or Validate Fix → recorded result → permitted solution, reward and next action.**

Show the statement, constraints, comparison policy and visible/hidden case counts before submission. A run is free experimentation. A custom-input run does not invent an expected answer. Submit checks all required cases and only all-pass acceptance completes a Practice problem.

Pending evaluation, a failed program, an access/capacity refusal and a platform outage have different feedback. Preserve source through a refused or failed request. A disabled keyboard action cannot bypass its button's rule. Another person's result is never available through a guessed identifier.

## Draft and source ownership

Drafts are scoped to learner, owning area, item and language. Switching languages preserves the previous language's draft. Source from an equivalent problem in another area is never used automatically.

| Caller | Initial source when opening |
|---|---|
| Challenge, Track or Daily | Device draft, otherwise retained accepted source for that same item/language, otherwise starter |
| Debug | Device draft, otherwise retained last submitted source for that case/language, otherwise broken starter |
| Code Lab | Its language scratch, otherwise that language's starter |
| Assessment | Its own acknowledged answer and permitted device recovery |
| Workspace | Its saved project file and explicit recovery choices |

State what was restored only when it actually was. Ordinary Practice drafts clear at sign-out or account change and are not cloud-saved projects. Debug's timed checkpoint is a distinct acknowledged record. The common editor does not extend a page's retention promise.

Reset confirms the source replacement and updates the corresponding local draft together. Cancel changes nothing. A failed starter read cannot blank the editor. Apply the owning area's active-run restrictions and retained-source restoration control.

## Hints and worked explanations

Hints are optional, authored and ordered. Reveal the lowest unseen hint; a re-read does not increase usage and reordering does not erase prior reveals. They cost no Credits and reduce no XP or skill evidence. Distinguish another hint, exhausted hints, none authored and delivery unavailable.

Inline hints remain usable without WizBit. Generated text cannot fill a missing authored hint. A live recorded test suppresses assistance through its account-level restriction, not merely by removing a local button.

An authored worked explanation unlocks only after the required acceptance. It is separate from private reference code and learner submissions. A failed later solve or source-code expiry does not relock it. Missing language coverage is stated; no private answer is substituted. Exhausted Debug windows, payments or a Give up control do not unlock the debrief.

## Acceptance and repeated work

Record acceptance, its required accepted-source capture and payable reward occasion coherently. Only then claim the item was solved. A closed page does not prevent finalization, and replay produces no duplicate solve, source entry, XP or evidence. Delayed reward delivery is described as delayed rather than making the solved problem payable again.

The first accepted language produces its Solutions entry. A first acceptance in another language may produce another entry, but no second first-solve award or evidence for the same owned problem. A subsequent accepted submission in the same language does not overwrite the first accepted source. New submissions may remain in the area's separate history while retained.

Show Solved before offering repeat practice, with its date and no-repeat-reward explanation. Solved status and earned rewards survive ordinary content changes, code expiry and progress resets. An independently authored problem in another Track or area remains a separate first-solve occasion.

## Results, rates and domain differences

Solutions stores the accepted-code collection; each area stores its own submissions/history. Expired detail, an empty history, pending work and an unavailable read remain distinct. No staff control can inspect private learner source.

The public Solve rate is the owning problem's distinct eligible solvers divided by its distinct eligible submitters, not accepted submissions divided by all submissions. Use the exact definition and sample minimum in Practice for both audiences. Debug keeps timed/practice Fix rates separate. Code Lab has no Solve rate.

Daily owns dates, bonus, catch-up and the streak. Debug owns timed windows, deadline checkpoints and allowance restoration. Tracks owns its fixed language and durable track completion. Assessment owns paper timing, marking and history. The shared workbench cannot generalize those into one timer or reward policy.

## Checks

Use identical wording in two independently owned problems and confirm no shared edits, completion or reward. Test draft precedence, language switching, free Run, all-pass Submit, hidden failures, free/exhausted hints, closed-tab acceptance, duplicate delivery, further accepted languages and aged-out source. Reuse behavior without sharing the learner's records across owners.
