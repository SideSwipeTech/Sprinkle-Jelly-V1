## Shared responsibility

Help makes approved assistance available in the current activity without becoming its controller. Domains supply allowed context, authored hints and confirmed outcome facts. Help returns the permitted guidance or message; it cannot run code, submit answers, change files, grade work or award progress.

There are two distinct systems: authored assistance and optional generated assistance. Normal WizBit guidance, knowledge-base answers, tips, hints and messages do not require a provider or Credits.

## Authored guidance

| Capability | Boundary |
|---|---|
| Page guide | The page's authored greeting/tips in their approved order |
| Hint ladder | The owning problem's free hints; no generated replacement or penalty |
| Product questions | Published knowledge-base answers with the required matching confidence and separation |
| Progress guidance | Explain the supplied Analytics/domain fact without creating another score |
| Next action | Present the authored permitted destination, never infer a new content gate |
| Outcome message | Present the confirmed event using the approved factual wording |

Weak or tied knowledge matches ask for clarification under the existing rule. Unavailable lookup is not missing knowledge, and neither authorizes a generated guess. Below-minimum Skills evidence cannot become a claim that the learner lacks ability. Missing hints and failed hint loading have different states.

A page can provide its own inline hints without WizBit. The fixed-corner character, Plain presentation and artwork fallbacks change presentation, not permissions or available facts. The shared capability adds no separate chat destination or persistent conversation archive.

## Messages, restrictions and nudges

Messages owns the complete 39-kind catalogue, expressions, tones, timing, queue, sticky handling and celebrations. A message's required fact makes sense without its optional friendly flourish. A celebration is not the only proof of completion and its absence does not undo a reward.

Present, Quiet and Suppressed remain different. Quiet permits requested help and relevant outcome/error feedback but no unsolicited guidance or celebration. A live recorded test suppresses the defined assistance across tabs and presentations. Administration has no learner companion. Keep independent restrictions independently active; releasing one cannot clear another.

Essential risk messages and confirmations remain in ordinary interface controls. Only explicit confirmation authorizes an action. The character is not a substitute for a destructive-operation dialog, and a suppressed companion is not permission to omit a required system warning.

The only proactive source is the existing Skills next action on Home. Apply Guidance's daily limit, cooldown, dismissal and busy-state rules. No backlog of withheld suggestions is delivered later, and shared reuse does not create promotional nudge producers.

## Optional generated assistance

| Action | Allowed contexts |
|---|---|
| Explain a passage | Selected permitted lesson text, not a course quiz |
| Analyse my code | Code Lab, personal/Course Workspace and the learner's retained accepted Solution |
| Explain this execution error | Permitted execution-error context in Code Lab or Workspace |

Assessments, course quizzes and active Challenge/Track/Daily/Debug solving do not gain generated answers. A saved accepted Solution is the separately permitted post-acceptance case. The response belongs to the invoking page, not the authored companion-message queue.

Build this capability switched off initially. Enable all three together only after their approved privacy, restriction, cost and recovery checks pass. While off, hide the generated actions and associated Credit surfaces; authored help remains usable. There is no per-page accidental activation or dead coming-soon control.

## Request, charging and recovery

**Journey:** Learner deliberately selects an action/context → validate eligibility and attachments → show price/balance → confirm → reserve and dispatch one request → show a labelled generated answer or honest failure → settle the same request.

Attach only the chosen owned source/passage or permitted visible error. No project crawling, unrelated files, hidden cases, reference answers, Notes, private identity or raw terminal history. Refuse detected credentials/restricted material before dispatch and reservation, identifying the attachment without repeating its secret. Oversized input is refused rather than silently truncated.

Only one generated request can be active per learner across the three actions. Repeated presses or refresh recover that request, not another charge. A new request remains distinct from retrying the old one. A changed quoted price requires renewed confirmation. Closing a panel after dispatch does not claim provider cancellation.

The domain's exact input/output bounds, provider eligibility, fallback rules and cancellation/settlement conditions remain in Generated Help. Recovery retains bounded request facts and a separate response for 24 hours, not original prompts/attachments or a permanent chat history. Spending history is separate. No request can edit files, tick tasks, submit code or change a verdict.

Membership-month Credits and calendar-month provider usage limits are separate. Positive Credits do not override a provider ceiling, restricted context or simultaneous-request refusal. Platform-wide cost controls must be configured before activation. Provider faults leave ordinary learning, coding and authored help usable.

## Administration, privacy and checks

The fixed Admin/Super Admin policy controls preparation, publication and live configuration. No staff tool reads learner questions, code or generated answers. Knowledge-base material and response copy are authored product content, not harvested learner conversations.

Only eligible non-identifying recurring product-help phrases contribute to Content Gaps under Guidance's threshold. Outages do not become demand. Topic Requests remains its separate deliberately submitted channel. Aggregate help counters never become a personal behavior profile.

Check authored help with AI off, missing/tied knowledge, inline hints without the character, fixed-corner fallback, Quiet and overlapping test restrictions. Test each generated context, credential refusal, explicit attachments, double requests, quoted prices, provider failure, closed-panel recovery, 24-hour expiry and both usage cycles. Essential actions must remain understandable without WizBit or AI.
