# Solutions

**Status:** Reviewed product definition  
[Shared](Shared.md) · [My Solutions](../domains/Practice/Solutions.md) · [Solving](Solving.md)

## Shared responsibility

Solutions receives accepted source from independent Practice areas and provides the learner's read-only My Solutions collection. It does not own a problem library, run a grader, award XP or grant content access.

Its four origins are Challenges, Tracks, Daily Challenges and Debug Detective. Code Lab runs, lesson examples, Assessment answers and Workspace files do not become Solutions entries. Sharing the editor does not add another origin.

## Capture

The producing area supplies a verified learner, owned problem identity, first accepted language/source, captured title/difficulty/classification, acceptance time and permitted origin-specific facts such as Track, scheduled date or Debug mode. The origin is established by that area, not chosen by the learner to obtain another reward.

Capture agrees with the durable acceptance, including when evaluation finishes after the page closes. A failed required capture must not be presented as a successfully saved solution. Retrying the same accepted outcome returns the existing entry.

There is at most one entry per learner, independently owned problem and language. Another accepted language may add an entry without another reward for that problem. Another acceptance in the same language does not overwrite the first accepted code. The producing area's ordinary submission history is the separate place for later retained attempts.

**Journey:** Practice accepts → record its first accepted source → open the exact saved entry → read source and any permitted explanation → return to the owning problem for further work.

## Shared collection facts

Home, Profile and collection views read the same saved-entry totals and difficulty/origin counts. An accepted-language entry is not automatically a new unique problem. Entries with expired code remain counted; a failed count is not zero.

Solutions supplies the accepted record and code only to its learner. Lists use the existing search, difficulty filter, paging and display preference. No consumer creates a public collection, staff-source viewer, Run/Submit control or export of learner code.

An editorial or Debug debrief comes from its content owner and follows that owner's acceptance-based unlock. It is not private grading reference code. Reading it creates no reward or skill evidence. A missing matching-language explanation is stated, not filled with a secret answer.

## Content changes and retention

Source edits never rewrite the saved code or difficulty captured at acceptance. State when current teaching content differs from the accepted code's context. Equivalent problems in separate areas remain separate entries; no text matching merges or reclassifies them.

Unpublish, Archive or safe Delete of a problem leaves its learner entries and required original facts intact. A deleted problem gets no misleading live link. This protection does not require maintaining a restorable Trash copy of the whole authored library.

The exact 90-day-or-recent-entry protections, independent category floors and summary lifetime are defined in My Solutions. Source-retention and submission-history collections are different even where their counts match. Code expiry explains Source no longer retained; a temporary read failure while source should exist offers a genuine retry. A re-solve does not promise to resurrect expired first-accepted code.

## Help, milestones and privacy

Optional generated analysis attaches only the learner's own available accepted source and follows Help/Credits. It does not run the program, change the verdict, create another entry or broaden the pre-solve help policy. Hide the action while generated assistance is disabled.

Collection milestones use the durable total once and provide only the approved celebration. No XP, achievement, public claim or inbox event is invented. Skipped presentation does not remove the milestone's underlying record.

Account erasure removes the entries and retained source through Solutions. It does not delete authored problems or instruct staff to read their private contents. Other pages may read permitted summaries or the owner's entry, never another learner's code.

## Checks

Accept identical independently owned problems, add another language, replay acceptance and fail a later submission. Verify origin/count consistency, exact-entry navigation, editorial separation, source expiry versus outage, retired problems, generated-help restrictions and once-only milestones. No integration may overwrite accepted code or create a shared reward identity.
