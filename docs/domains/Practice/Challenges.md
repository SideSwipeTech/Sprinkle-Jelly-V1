## Purpose and ownership

Challenges provides independently authored coding problems that learners can solve in one or more supported languages. Every Challenge owns its statement, cases, starters, hints and learner results. It is not a reusable record for Tracks, Daily or Debug. A similar problem created there is separate and solving it here completes nothing elsewhere.

The shared practice workbench, editor, language catalogue, execution and evaluation provide the familiar experience. Challenges owns its catalogue, submissions, acceptance, history, reward occasion and skill contribution. It has no timed mode, proctoring, partial marks or streak.

## Find a problem

Browse every published standalone Challenge through a paged catalogue, not just the featured items. Search text and filter by difficulty, topic and personal status. Show the actual range and total when available; a total that cannot be established is not estimated as exact. Keep topic choices meaningful rather than hiding them merely because another filter changed.

| Status | Meaning |
|---|---|
| New | No valid submission and not solved |
| Submitted | At least one non-platform-failure submission, not yet solved |
| Solved | This learner has an accepted solve of this Challenge |
| All | Every currently available item matching the other filters |

Each row or card identifies its title, difficulty, relevant topics/languages, learner status and the XP the shared difficulty award actually pays. Show **Solve rate** for learners and administrators using the definition in Practice, with eligible attempted/solved counts. A small population is Not enough data; an unavailable statistic is not zero. Track-owned problems are not in this catalogue.

Empty catalogue, no filter matches and failed loading are different states. Offer a topic request for an empty library, clearing filters for no matches, and Retry for a failure. Never fill an empty catalogue with fake learner-ready problems.

### Random Challenge

Choose uniformly from unsolved published standalone Challenges matching the current filters. Do not silently serve a solved item or ignore the filters. With no candidate, distinguish all matching problems already solved from no published problems matching. Stay on the page and explain; a failed lookup re-enables the action.

## Open and solve

**Workflow:** Browse or Random Challenge → read the statement → choose a supported language → write code → Run → Submit → result → saved solution and eligible reward.

The statement includes structured input/output descriptions, constraints, visible examples, hidden-case count and the comparison policy. Console programs and SQL-query tasks use the shared practice interfaces. SQL supplies the allowed schema and visible datasets; hidden datasets remain hidden.

Only languages authored and checked for that Challenge can be selected. Choosing another language never discards the previous language's work. Code over the permitted size is refused before execution with its limit stated.

Seed the editor from this learner's device draft, otherwise retained accepted code for that same Challenge and language, otherwise the starter. Announce a restored draft only when one was really restored. Local saving is separate from platform storage; unavailable local saving is explained. Signed-out or another-account sessions receive none of the prior learner's source.

Run checks visible cases or supplied custom input for experimentation. A custom-input run shows output without a manufactured verdict or expected-case result. Run creates no submission, completion or reward. The shared keyboard shortcuts perform the same actions as Run and Submit; disabled shortcuts remain inert.

Submit checks all visible and hidden cases. Every required case must pass. Show pending grading honestly; name a failing visible case where available, or state that a hidden case failed without disclosing values. A program with no usable output is explained through its output, not an invented case result.

Two rapid submissions of the same request produce one recorded outcome. A platform or capacity failure creates no valid failed attempt, does not change personal status or solve rate, and keeps the code available for retry. A submitted job that completes after the page closes is still finalized by the platform.

## First acceptance and later practice

The first acceptance records the solve and date, the learner's accepted source in Solutions, the difficulty-based XP occasion and one skill contribution for this owned Challenge. They must not disagree about whether acceptance was recorded. Temporary downstream delay is shown honestly; replay never pays or counts twice.

The skill contribution uses the difficulty and classification at the time of the solve. Later edits affect future activity, not historical evidence. Hint reveals, runs and another acceptance do not multiply it. Active solving time follows the shared rules and attributes to the problem's primary skill.

Reopening a solved Challenge shows that it is solved before the learner presses a control and explains that re-solving earns no further reward. An accepted solve in another supported language can add that language's first accepted source to Solutions, but does not award this Challenge again. A separately created Track or Daily problem remains eligible for its own reward.

A later failure cannot clear Solved or overwrite accepted code. A repeated accepted submission in the same language does not replace the first accepted source in Solutions; its newer source may remain in submission history while retained.

## Hints and explanations

Hints form an optional ordered ladder. Reveal the next unseen rung for free. Using any number of hints changes no XP or skill judgment. Reopening or reordering does not increase recorded hint use. Keep the inline hints usable without WizBit and separate no hints, exhausted hints and failed loading.

An optional worked solution is authored and validated separately for each language. It unlocks after the learner's first accepted solve and is reachable from both the problem and its Solutions entry. It is never the private reference answer or another learner's work. Missing language coverage may offer a labelled different-language explanation without claiming equivalence. Unavailable content offers retry; missing content is not filled from a secret answer.

Acceptance remains the unlock even when saved source later expires. There is no pre-solve paid reveal, failure-count unlock or give-up action. An advisory link to a paired Debug case is independent practice, not shared completion or grading content.

## History and content changes

Personal submission history shows verdict, language, cases passed and date/time, newest first. Open only the learner's own source while retained. Distinguish empty history, unavailable history, pending work and expired detail. Retain submission detail within the shared ninety-day window or the learner's recent eighty Challenge submissions, whichever retains more; track submissions have their own allowance.

The durable solve and its date outlive retained code. If source expired, reopen with the available starter and explain the missing code while leaving Solved visible. Do not offer fake recovery.

A changed published statement or editorial is current content; show that the learner's saved code is unchanged and was accepted before the change. Do not silently claim current test cases are the ones used for an old submission. If cases materially change during grading, reject that mismatched outcome as a content conflict and let the learner resubmit without treating it as their error.

**Unpublish / Return to Draft** temporarily removes a published Challenge from learner availability and returns the same item to editing. Preserve learner drafts, solves, rewards and retained Solutions entries. Republish only after the normal checks; returning the item does not grant fresh first-solve rewards. This optional action is distinct from final Archive and is not required before an ordinary direct update. Super Admin performs the live withdrawal under the fixed role policy.

Archive or Delete prevents new solving of the removed item while preserving earned solves, rewards and retained Solutions entries. Keep local drafts intact and explain the content's unavailability. Safe removal does not reach a similar problem in another area. The authoring document owns the common confirmation and dependency safeguards.

An explicit administrator-authored prerequisite may restrict a not-yet-started problem. Show the requirement and the learner's status with a link to satisfy it. Order, difficulty, XP and skill estimates never create inferred locks. Adding a prerequisite does not unexpectedly lock an already-started item.

## Staff capabilities and checks

Staff create, read, update, preview, validate, publish, unpublish/return to draft, archive and safely delete Challenges using the shared form and the fixed Admin/Super Admin responsibilities. They manage each problem's languages, starters, cases, hints, optional worked explanations and advisory Debug link. Direct live edits are allowed after the same validity checks; ordinary corrections do not require duplicating an entire problem. Staff review content solve rates and aggregate timing/hint signals without accessing learner source.

Account erasure removes this learner's solves, submissions, hint records and drafts, while Solutions and Economy remove their own personal records. Authored Challenges remain separate; anonymous aggregates retain no personal attribution.

Check filters and Random Challenge, independent Track content, draft precedence per language, custom input, all-case acceptance, hidden failures, free hints, double submission, completion after a closed tab, repeat solves, a further accepted language, source expiry and unsafe content changes. Verify Unpublish removes availability without removing earned history and that republishing the same item does not pay again. Verify the same content Solve rate for learners and staff without creating a learner leaderboard.
