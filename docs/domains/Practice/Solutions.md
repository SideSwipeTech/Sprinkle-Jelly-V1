# Solutions

**Status:** Reviewed  
[Practice](Practice.md)

## Purpose

The learner-facing name is **My Solutions**. It is a read-only collection of the learner's accepted code, organized under Challenges, Tracks, Daily Challenges and Debug Detective. Solving and editing happen on each owning problem page, not here.

Solutions owns the saved acceptance record and retained source, not the problem library. It creates no problems, grades no code, awards no XP and computes no new skill evidence or Solve rate. Staff do not manage or inspect learner code here.

## Capture and independent origins

The first accepted submission for a learner, owned problem and language creates its solution entry automatically. Learners never need to press Save Solution. Acceptance and required source capture must agree, including when the learner closes the page before seeing the result.

Each entry keeps its originating area, problem identity, title, difficulty when solved, language, solve date, available classification and relevant track/date/mode information. Origins are independent: solving a Challenge does not create a solution for a similar Track or Daily problem. Separate copies produce separate entries and follow their owning areas' first-solve reward rules.

There is at most one retained entry per learner, owned problem and accepted language. A further accepted language can create another entry without paying that same problem's XP again. Re-solving in the same language does not overwrite the first accepted source or file a second entry. Later source may remain on that problem's submission-history page while retained.

A failed, late or racing submission cannot replace accepted source. If acceptance could not be recorded, the problem page reports the storage/platform failure and offers a real retry instead of claiming an accepted solution was saved. Repeated processing cannot double the entry or its count.

## Browse and open

**Workflow:** Open My Solutions → choose a category or search/filter → open an entry → read accepted code and any available worked explanation → return to the problem for further practice.

Show newest entries first, with search, difficulty filters, pagination and list/grid choice. Remember that display preference through the personal preferences experience rather than keeping a separate contradictory preference. Counts represent saved accepted entries, not unique problems regardless of language and not the number of submissions.

The total equals the four category counts, and difficulty totals describe that same collection. Entries whose code expired remain counted. A fresh accepted entry updates the relevant counts; temporarily unavailable data is not replaced with zero. Empty collection, no search matches and failed loading are different states.

The post-acceptance handoff opens the exact new entry where possible, not an unrelated top-of-list item. Visiting an entry must not fail just because optional recording of that visit failed. Solutions is not a Continue target for unfinished coding.

## Entry detail

Show the learner's saved source in a read-only editor, its language, title, solve date, captured difficulty and only measurements actually recorded. Challenges, Tracks and Debug may show cases passed and runtime. Daily may show its awarded XP and scheduled date. Debug also states whether its source was accepted in timed or practice mode.

Missing measurements are omitted or explained, not invented as zero. Distinguish the acceptance that supplied the displayed code from a later successful resubmission. No Run, Submit, source editing or project creation is provided from this read-only view.

### Worked explanations

An authored editorial or Debug debrief can appear beside the learner's code once its owning area's acceptance rule unlocked it. It is separate from the private reference answer and never another learner's code. The archive does not author or publish that explanation.

Use the matching language when available. If none is published in that language, state that and optionally offer another explicitly labelled language. Missing, unavailable and not unlocked are different situations. Hidden datasets, answer keys and internal notes are never substituted for a missing explanation.

An unlocked explanation does not relock when accepted source expires or WizBit is unavailable. There is no pre-solve reveal, give-up exchange, paid unlock or reveal merely because attempts were exhausted. Reading an explanation changes no score, reward or skill figure.

## Code retention

The solve entry lasts for the account's lifetime; its source code is retained for a bounded period. Keep accepted source while it is within ninety days **or** among the learner's most recent entries in that category, whichever preserves more.

| Category | Recent accepted-code entries kept beyond the window |
|---|---:|
| Challenges | 80 |
| Daily Challenges | 30 |
| Tracks | 80 across all of the learner's tracks |
| Debug Detective | 40 |

These are retention protections, not limits on problems, solutions or earning XP. For example, ninety recent Challenge solutions inside the time window can all retain their source; the eighty-entry protection does not delete the extra ten. Each category is independent.

When source expires, keep the title, solve date, language, captured facts and counted entry, with a clear Source no longer retained message. Do not show an empty code editor, error styling, Retry, Restore or a promise that support can recover the source. A source fetch that fails while code should still exist is a genuine temporary error with an appropriate retry, not false expiry.

Source retention and submission-history retention are separate collections even where their protected counts match. Re-solving does not silently replace the original source or promise to resurrect expired accepted code.

## Changed, archived or deleted problems

Editing a problem never rewrites the learner's accepted source or the difficulty stamped at its acceptance. When presenting a current statement or explanation beside older code, clearly say that the code is unchanged and the displayed teaching content is current. Offer the owning area's learner-safe change information where available rather than pretending it is an archived original editorial.

Archiving or deleting an authored problem does not delist, uncount or blank its solution entries. State that the original problem was retired or is no longer available and preserve the accepted record and source for its normal retention period. Do not offer a broken link to a deleted problem or imply that a permanently removed problem will return.

Only that originating item is affected. A Challenge and separately created Track exercise remain separate even with identical text. There is no cross-domain search for similar content to merge or reclassify entries.

The platform need not preserve a whole restorable problem library as a Trash mechanism to preserve accepted history. The retained entry's required original facts and source remain available without falsely promising a historical statement or editorial that is not kept.

## Optional generated analysis

When the shared generated-help capability is enabled, the learner can explicitly request analysis of their own saved accepted code. It runs no code and changes no source, verdict, count, reward or evidence. Clearly label the response as generated assistance to verify.

Show the current Credit price before confirmation, attach only the selected owned source, and handle unavailable/pruned code honestly. The action cannot attach another learner's source or silently analyse an unrelated buffer. A changed price asks for a renewed confirmation rather than charging an unseen amount.

A duplicate press or retry of the same request does not purchase another request. The shared one-active-request rule applies across areas. Failed requests follow shared release/refund behavior. No generated-help control is shown while that capability is disabled.

## Milestones, privacy and data

Celebrate saved-solution totals of 5, 10, 25, 50, 100 and 250 at most once each. These are small review milestones, not achievements, XP grants, unlocks or notifications. Source expiry does not remove counted entries or replay a milestone. A missing total does not trigger an invented celebration, and an unavailable companion does not block reading.

Only the learner can read their solutions. There is no public collection, sharing, export of learner code, staff view, support bypass or promotion of learner source into an editorial. An unauthorized entry is indistinguishable from a missing private entry. Activity time may contribute at the Practice-group level but produces no skill evidence.

Account erasure removes the learner's entries and retained source; it does not delete the authored problems of the source areas. Protected holds delay deletion honestly and incomplete removal is not described as finished. There is no ordinary admin CRUD for learner solutions: the owning solve captures them, normal retention removes eligible source, and account erasure removes the personal records.

## Checks

Accept a new language, repeat an acceptance, fail after success, close the tab during finalization and solve equivalent independent problems in different areas. Confirm origin-specific entries, no overwriting and accurate counts. Check exact-entry handoff, missing metrics, same-language editorial, code expiry versus fetch failure, source deletion, privacy, generated-request retry and once-only milestones. No stored learner source should become accessible through staff authoring.
